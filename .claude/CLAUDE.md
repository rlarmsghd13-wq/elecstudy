# 전력경제 공부 볼트 — Claude 작업 규칙

이 폴더는 사용자의 **전력경제 공부용 Obsidian 볼트**이자 GitHub 저장소 `rlarmsghd13-wq/elecstudy`다.
**공개(public) 저장소**라서 올리는 것은 모두 인터넷에 공개된다.

기본 흐름: 사용자가 노트를 먼저 쓴다 → Claude가 검토하고 보완한다 → 모르는 개념은 따로 정리한다 → 폰 사진 속 표·수식을 옮긴다 → GitHub에 올린다.
사용자는 번거로운 걸 싫어한다. "검토해줘", "사진", "올려줘"처럼 짧게 말해도 아래 작업을 끝까지 한다.

## 1. "검토해줘" / "정리했어" → 노트 검토·보완

1. 대상: 사용자가 파일을 지정하면 그 파일, 아니면 `git status`로 새로 생기거나 바뀐 노트.
2. **고치기 전에 사용자 원본을 먼저 커밋한다** (`[원본] …`). 그래야 GitHub 기록에서 Claude가 바꾼 부분이 비교된다.
3. 사용자의 문장과 구성은 유지한다. 통째로 다시 쓰지 않는다.
4. Claude가 더한 내용은 callout으로 구분한다.
   - 틀린 내용 → 그 문장 바로 아래 `> [!warning] 수정` — 무엇이 왜 틀렸는지
   - 빠진 내용·맥락 → `> [!note] 보충`
   - 시험 포인트·암기 요령 → `> [!tip] 포인트`
   - 오탈자·맞춤법·마크다운 형식은 표시 없이 바로 고친다.
5. 요금, 정산 규칙, 시장 제도, 법령, 통계 수치는 자주 바뀐다. 확실하지 않으면 웹에서 확인하고 `(2026.9 기준, 전력거래소)`처럼 기준 시점과 출처를 붙인다.
6. 끝나면 고친 내용을 채팅에 3~5줄로 요약하고 4번(업로드)까지 진행한다.

## 2. `??` 표시 / "이거 모르겠어" → 개념 정리

- 사용자는 이해 안 되는 말 뒤에 `??`를 붙인다. 예: `정산조정계수??`
- 노트에서 `??`를 찾아 `개념/<개념명>.md`를 만들고(이미 있으면 보강), 원문의 표시를 링크로 바꾼다: `정산조정계수??` → `[[정산조정계수]]`
- 개념 노트 형식:

  ```markdown
  ---
  aliases: [영문명, 약어]
  tags: [개념]
  ---
  # 개념명
  > 한 줄 요약

  ## 쉽게 말하면
  비유나 숫자 예시로.

  ## 정확한 정의
  시험 답안 수준. 수식이 있으면 수식과 변수 설명.

  ## 연결 개념
  [[다른 개념]]과의 관계, 이 개념이 쓰이는 곳.

  ## 헷갈리는 포인트
  ```

- 설명은 비전공자 눈높이에서 시작해 시험 수준 정의까지 올라간다.

## 3. "사진" / "사진 넣어줘" → 폰 사진 속 표·수식 옮기기

1. `H:\내 드라이브\전력경제_사진함\`에서 `완료` 폴더를 뺀 이미지·PDF를 오래된 순으로 읽는다. 작업 폴더 밖이라 접근이 막히면 이 경로를 `request_directory`로 요청한다.
2. 변환 규칙
   - 표 → 마크다운 표
   - 수식 → LaTeX. 문장 속은 `$...$`, 따로 쓰는 수식은 `$$...$$`. 수식 아래에 변수 설명과 단위.
   - 그래프·도식 → 새로 그린다. 흐름도·구조도는 Mermaid, 그래프는 matplotlib로 PNG를 만들어 `첨부/`에 저장하고 `![[파일명.png]]`로 넣는다. 한글 폰트는 `plt.rcParams['font.family'] = 'Malgun Gothic'`, `plt.rcParams['axes.unicode_minus'] = False`.
   - 다시 그리기 어려운 그림만 원본 사진을 쓴다. Pillow로 필요한 부분만 잘라 긴 변 1600px JPEG로 다시 저장해서 `첨부/`에 둔다. 다시 저장하면 EXIF(촬영 위치 등)가 지워지므로 원본 파일을 그대로 올리지 않는다.
   - 교재 본문 문장 → 그대로 베끼지 말고 요약해서 다시 쓴다. 공개 저장소이고, 공부에도 그게 낫다.
   - 흐리거나 확신이 낮은 부분 → `> [!question] 확인 필요`
3. 넣을 위치
   - 노트에 `[사진]` 자리표시가 있으면 오래된 사진부터 순서대로 채운다.
   - 없으면 내용을 보고 가장 관련 있는 노트·섹션에 넣는다.
   - 그래도 애매하면 사용자에게 묻는다.
4. 처리한 사진은 `전력경제_사진함\완료\`로 옮긴다. 지우지 않는다.
5. HEIC 사진이면 `pip install pillow-heif`로 JPEG 변환한 뒤 읽는다.

## 4. "올려줘" / 작업 마무리 → GitHub 업로드

- 1~3번 작업이 끝나면 따로 말하지 않아도 커밋하고 푸시한다.
- 커밋 전에 `git status`로 의도하지 않은 파일(대용량, 개인 파일, 원본 사진)이 섞이지 않았는지 확인한다.
- 노트가 생기거나 없어지면 `README.md` 목차를 갱신한다. README는 GitHub에서도 열리도록 표준 링크 `[이름](경로.md)`를 쓰고, 경로의 공백은 `%20`으로 쓴다.
- 커밋 메시지는 한국어로, 앞머리에 종류를 붙인다: `[원본]` 사용자 원본, `[검토]` 수정·보완, `[개념]` 개념 노트, `[사진]` 사진 옮김, `[설정]` 구조·설정
- 인증은 Git Credential Manager에 `rlarmsghd13-wq` 계정으로 저장돼 있다. 푸시가 인증 오류로 실패하면 사용자에게 알린다.

## 표기 규칙

- 노트 안 링크는 Obsidian 위키링크 `[[노트명]]`. 보이는 글자가 다르면 `[[SMP|계통한계가격]]`.
- 개념 노트 파일명은 짧은 대표 이름(`SMP.md`, `정산조정계수.md`), 다른 이름은 `aliases`에 넣는다.
- 용어가 처음 나올 때 한·영 병기: `계통한계가격(SMP, System Marginal Price)`
- 수식 안의 단위는 `\text{원/kWh}`처럼 쓴다.
